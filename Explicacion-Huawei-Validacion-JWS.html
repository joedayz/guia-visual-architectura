Huawei SysIntegrity: validar el JWS en el banco, no llamar a Huawei

La tabla comparativa del documento deja abierto si smp-device-integrity-service valida la firma en local o llama a una API de Huawei. El diagrama de despliegue ya dibuja la salida a Huawei. Huawei no tiene un descifrado remoto como Google: la verificación es local, con la cadena hasta la raíz CBG.

Postura: el servicio verifica el JWS en local, como documenta Huawei. No hay que llamar a Huawei desde el banco para "descifrar" el token. La app sí habla con Huawei para obtener el JWS. El diagrama de despliegue no debería pintar una flecha del servicio a Huawei, salvo OCSP/CRL si se decide consultarlos.
  1. Parsear header, payload y firma.
  2. Validar la cadena x5c contra la raíz Huawei CBG Root CA (anclada, no el almacén del sistema).
  3. Comprobar que el certificado hoja es de sysintegrity.platform.hicloud.com y que la cadena tiene tres niveles.
  4. Verificar la firma, el nonce, la frescura, apkPackageName y apkCertificateDigestSha256.
  5. Exigir basicIntegrity = true. Huawei no documenta evaluationType: esa diferencia con Play Integrity queda como riesgo aceptado.

3. basicIntegrity no es MEETS_DEVICE_INTEGRITY

Play Integrity, en este proyecto, exige MEETS_DEVICE_INTEGRITY y PLAY_RECOGNIZED. Huawei entrega un booleano. Huawei dice que la evaluación ocurre en el TEE durante el arranque seguro, pero el JWS no trae un flag equivalente a HARDWARE_BACKED / evaluationType (eso es de SafetyNet de Google, y el diagrama de secuencia del HTML de este proyecto lo llegó a nombrar por analogía).

4. Qué no haríamos

El servicio no llama a Huawei a descifrar

A quitar del despliegue
  • No inventar un cliente HTTP a Safety Detect desde smp-device-integrity-service.
  • No confiar en el almacén de CAs del sistema operativo: anclar el cer de Huawei CBG Root CA / G2 que publica Huawei, con proceso para rotarlo.
  • No usar checkSysIntegrityOnLocal como fallback de ENFORCE: Huawei lo reserva a cuando no hay servidor suyo, y el resultado no viene firmado como JWS de SysIntegrity.
  • Opcional: consultar OCSP/CRL de la cadena. Eso sí sería una salida a Internet, distinta de "la API de Huawei", y habría que dibujarla aparte si se adopta.

5. Ejemplo de verificación (Java, ilustrativo)

Decision verifyHuawei(String jws, Expected exp, byte[] expectedNonce) {
    SignedJWT jwt = SignedJWT.parse(jws);
    List<X509Certificate> chain = parseX5c(jwt.getHeader().getX509CertChain());
    if (chain.size() != 3) return deny("HUAWEI_CHAIN_LENGTH");

    X509Certificate leaf = chain.get(0);
    verifyChainAnchored(chain, pinnedCbgRoot);          // raíz CBG en el keystore de la app, no cacerts
    if (!leafMatchesHostname(leaf, "sysintegrity.platform.hicloud.com"))
        return deny("HUAWEI_LEAF_HOST");

    if (!jwt.verify(new RSASSAVerifier((RSAPublicKey) leaf.getPublicKey()))
        && !jwt.verify(new RSASSAVerifier((RSAPublicKey) leaf.getPublicKey()) /* PS256 si alg=PS256 */))
        return deny("HUAWEI_BAD_SIGNATURE");

    JSONObject p = payload(jwt);
    if (!constantTimeEquals(b64(expectedNonce), p.getString("nonce"))) return deny("HUAWEI_NONCE");
    if (nowMs() - p.getLong("timestampMs") > 120_000)                 return deny("HUAWEI_STALE");
    if (!exp.packageName.equals(p.getString("apkPackageName")))       return deny("HUAWEI_PACKAGE");
    if (!p.getJSONArray("apkCertificateDigestSha256").toList().contains(exp.certDigestB64))
        return deny("HUAWEI_CERT_DIGEST");
    if (p.has("appId") && !exp.appId.equals(p.getString("appId")))    return deny("HUAWEI_APP_ID");
    if (!p.getBoolean("basicIntegrity"))                              return deny("HUAWEI_BASIC_INTEGRITY");
    return allow();
}

El nonce de Tier 1 es el del challenge en Redis. El de Tier 2 se recalcula como en el HTML de replay: SHA256(método | ruta | SHA256(cuerpo) | deviceid | timestamp), y se registra en Redis para no repetirlo.
